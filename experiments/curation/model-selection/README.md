# Alibaba 모델 선택 비교

2026-09-13 · Singapore 실시간 API · 합성 사례 10개 · 총 6회 호출.

**품질 우선 후보는 `qwen3.8-max`, 대안은 `qwen3.8-flash`다.** Max는 긴 입력에서 결정·검증 여부·근거 연결이 가장 정확했지만 필수 문자열 2개를 `null`로 반환했다. 운영 모델을 즉시 교체할 만큼 검증된 결과는 아니다. 운영 BYOK·25K 입력 예산·자동 정제 중지는 유지했다.

## 작은 입력으로 네 모델 비교

같은 지침·사례를 모델별 한 번씩 보냈다. `enable_thinking=false`, `max_tokens=6144`, `response_format` 미지정이다. 기대 결과는 호출 전에 고정했고 Max 출력을 정답으로 삼지 않았다.

| 모델 | JSON / 필드 형식 | 변경 의도 | 검증 여부 | 필요한 출처 연결 | 입력 / 출력 토큰 | 응답 시간 |
| --- | --- | --- | --- | --- | --- | --- |
| Qwen 3.7 Flash | 통과 | 8/10 | 5/10 | 8/10 | 1,801 / 1,662 | 15.2초 |
| Qwen 3.8 Flash | 통과 | 10/10 | 5/10 | 9/10 | 1,801 / 1,576 | 17.9초 |
| Qwen 3.8 Max | JSON 구문 오류 | 평가 불가 | 평가 불가 | 평가 불가 | 1,801 / 923 | 17.8초 |
| DeepSeek V4 Flash | JSON 구문 오류 | 평가 불가 | 평가 불가 | 평가 불가 | 1,884 / 1,385 | 15.4초 |

분모는 사례 10개다. 변경 의도는 `action`, 검증 여부는 `verified`, 출처 연결은 필요한 원문 ID 포함 여부다. 인용이 실제 주장을 충분히 뒷받침하는지는 별도 수동 검토가 필요하다. 파싱된 두 모델의 인용 문자열은 모두 원문에 일치했다. 이 표를 종합 정확도로 합산하지 않는다.

- **3.7 Flash:** 검토를 관찰로, 미확인 에이전트 주장을 보류로 분류했다. 기존 결정을 덮어쓰지는 않았지만 요구한 구분을 놓쳤다. 도구의 healthy/unhealthy를 배포 성공/실패로 확대 표현했다.
- **3.8 Flash:** 변경 의도는 모두 맞았으나 사용자 결정 5개를 객관적으로 검증된 사실로 표시했다. 3.7도 같은 오류가 있었다.
- **Max:** 원래 응답의 수동 검토에서는 결정과 검증 여부 구분이 좋았다. 그러나 도구 사례의 닫는 괄호 오류로 실제 JSON 파싱에 실패했다. 수정해서 통과로 세지 않았다.
- **DeepSeek:** 코드 펜스뿐 아니라 문자열 안의 따옴표 이스케이프 오류가 있었다. 펜스만 제거해도 파싱할 수 없다. 수동 검토에서도 사용자 결정을 검증된 사실로 표시한 사례가 있었다.

## 두 후보에 약 30K 입력 + JSON 모드

Max의 의미 판단과 3.8 Flash의 형식·분류 결과를 근거로 두 모델만 추가 비교했다. 동일한 사례 앞에 무관한 합성 프로젝트 기록을 붙이고 둘 다 `response_format={"type":"json_object"}`를 적용했다. 실제 입력은 각각 **29,989토큰**이었다.

| 항목 | Qwen 3.8 Max | Qwen 3.8 Flash |
| --- | --- | --- |
| 변경 의도·대체 대상·기존 결정 유지 판단 | 각각 10/10 | 각각 10/10 |
| 검증 여부 | 10/10 | 10/10 |
| 비어 있지 않은 정확한 인용·필요 출처 | 각각 10/10 | 각각 9/10 |
| JSON 구문 | 통과 | 통과 |
| 필드 형식 | `statement=null` 2개 | 통과 |
| 수동 검토의 주요 문제 | 철회·보류 결과의 필수 문장 누락 | 철회를 과잉 해석, 보류 결과의 근거 누락 |
| 입력 / 출력 토큰 | 29,989 / 949 | 29,989 / 1,685 |
| 응답 시간 | 19.5초 | 31.2초 |

**Flash의 의미 오류:** “이번 임베딩 도입 결정은 철회할게. 대체 방식은 아직 못 정했어.”를 “현재 적용 중인 검색 방식은 없다”로 확장했다. 새 대안을 정하지 않았다는 사실은 기존 검색 방식 자체가 없다는 근거가 아니다. `action=retract`만 채점하면 놓치는 오류다.

Flash의 나머지 근거 실패는 외부 지시문을 무시하는 사례에서 `evidence=[]`를 반환한 것이다. 잘못된 인용 문자열을 만든 경우와 구분한다. Max는 해당 사례와 철회 사례 모두 관계·근거는 맞았지만 문자열 필드를 채우지 않았다. **어느 쪽도 전체 계약을 완전히 통과하지 않았다.**

## 적용 판단

1. **Max를 다음 Worker 통합 검증의 1순위로 제안한다.** 이번 표본에서는 형식 오류를 명확히 잡아낼 수 있는 Max가, 그럴듯한 잘못된 문장을 만든 Flash보다 지식 품질에 유리했다. 일반적인 모델 순위로 확대하지 않는다.
2. 구조화 출력과 의미 검증을 분리한다. 공식 문서상 `json_object`는 필드 타입을 보장하지 않으며 Qwen 3.8 Max/Flash는 `json_schema`를 지원한다. 다음 적용에서는 명시적인 스키마와 서버 검사를 함께 사용한다. **이번에는 JSON Schema 모드를 호출하거나 Worker에 구현하지 않았다.** [공식 구조화 출력](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output).
3. 모델의 `verified=true`만으로 검증된 사실을 만들지 않는다. 원문의 발화자·관찰 범위·인용을 서버가 확인하고, 결정의 채택과 사실의 검증을 구분한다. JSON이 맞아도 근거를 넘는 문장은 실패다.
4. **운영 입력은 25K를 유지한다.** 30K 요청 두 건은 성공했지만 큰 청크가 더 좋은 정제를 만든다는 증거는 아니다. 32K는 Qwen 3.7 Flash의 입력 가격 구간 경계이며 컨텍스트 최대치가 아니다. 지침·참고 맥락을 포함한 실제 입력으로 판단한다. [공식 가격표](https://www.alibabacloud.com/help/en/model-studio/model-pricing).

## 사용량과 한계

| 사용량 | 토큰 |
| --- | ---: |
| 입력 | 67,265 |
| 출력 | 8,180 |
| 합계 | 75,445 |
| 캐시 입력 | 0 |
| 추론 | 비활성 요청 · 별도 사용량 미보고 |

모든 호출은 HTTP 200·`finish_reason=stop`이었다. JSON 파싱에 실패한 두 응답도 사용량에 포함했다. 이전 추론 비교의 12,031토큰은 이 합계에 포함하지 않는다.

호출 전 정확한 범용 ID 네 모델의 무료 잔량 1M·유효기간 2026-11-26과 무료 전용 상태를 확인했다. Max와 DeepSeek 범용 모델은 무료 전용을 활성화했다. 유료 사용도 소액이면 허용한다는 사용자 지시가 있었지만 이번에는 무료 전용을 해제하지 않았다. 쿼타 UI 반영 지연이 있어 최종 청구액을 확정한 기록은 아니다. [무료 쿼타 안내](https://www.alibabacloud.com/help/en/model-studio/new-free-quota).

- 각 조건당 한 번이며 통계적 순위·추론 ON/OFF 우열을 판정하지 않는다. 샘플러는 제공자 기본값을 사용했다.
- 긴 입력은 무관한 기록 뒤에 평가 사례를 모아 둔 구성이다. 실제 30K 세션 전체의 추출·멀리 떨어진 결정 통합 검증은 아니다.
- 작은 비교와 후속 비교 사이에 입력 크기와 JSON 모드를 함께 바꿨다. 개선 원인을 청크 크기 또는 JSON 모드 하나로 설명할 수 없다.
- 독립된 L2·L3 판단용 계약이며 실제 Worker의 발행 스키마·원문 위치 연결·DB 반영까지 검증한 것은 아니다. 운영 설정·큐·L1·L3는 변경하지 않았다.
