# DeepSeek 추론 비용 가설

고정 모델 `deepseek-v4-flash`, Singapore 실시간 API. 운영 설정·큐와 독립적이다.

호출 전 가설: 작은 명시적 변경은 추론 OFF도 처리할 수 있지만, 늦은 수집·충돌·에이전트 주장 구분에서는 high가 유리할 수 있다. 6개 기존 합성 사례의 기대 결과를 고정하고 3개씩 2묶음 × OFF/high로 최대 4회만 비교한다. 순서를 교차하고 재시도하지 않는다. 출력 상한 8,192, 보고 토큰 누계 30,000 초과 또는 오류에서 중단한다. 마지막 호출까지 포함한 엄격한 누계 상한은 아니며 입력은 작은 합성 자료다.

기준은 action·target·독립 검증 오인·정확한 근거이며, high를 정답으로 삼지 않는다. 원문·reasoning_content·비밀을 저장하지 않고 합성 답변과 제공자 usage만 파일에 남긴다. DB를 기동하지 않는다. 이는 의미 판단의 작은 탐색이며 실제 Worker 발행 검증이나 30K 입력 품질 평가를 대체하지 않는다.

## 결과 · 2026-09-14

| 설정 | 기대 구조 전체 일치 | 입력 | 출력 | 입력 중 캐시 | 출력 중 추론 | 호출 평균 |
| --- | --- | --- | --- | --- | --- | --- |
| OFF | 3/6 | 1,106 | 738 | 512 | 미보고 | 4.1초 |
| high | 5/6 | 1,106 | 2,934 | 512 | 2,138 | 14.8초 |

4회 모두 HTTP 200·JSON 출력, 재시도 없음. 총 입력 2,212·출력 3,672 = 5,884토큰이다. 캐시 1,024는 입력에 포함되고 추론 2,138은 출력에 포함된다.

- OFF: 제안을 unconfirmed로 분류했고, 늦게 수집된 과거 발언을 action=supersede로 출력했다. 후자는 설명에서는 시간 관계를 언급했지만 구조화 action이 잘못되어 안전하게 채택할 수 없다. 충돌 대상 ID도 빠졌다.
- high: 과거 발언·검토 의견·충돌 대상을 구분했다. 다만 에이전트의 미검증 완료 주장에 기존 결정 ID를 target으로 넣었다. 검증 완료로 오인하지는 않았지만 기대 계약인 null과 달랐다.
- 두 설정의 모든 인용 문자열은 제공한 합성 근거와 일치했다. 작은 사례에서 high는 출력 토큰이 약 4배였다. 순서 교차 중 후행 요청만 캐시가 잡혔으므로 처리시간 차이를 추론 비용만으로 단정하지 않는다.

**잠정 판단: high 유지, 먼저 중복 출력·실패 재시도·페이지 재조립의 낭비를 줄인다.** 전환 실험의 action 계약은 실제 Worker의 Claim 출력 계약과 다르다. 표의 엄격한 일치율은 이 6개 합성 사례의 계약 검사이며 일반 정확도·실제 원문 품질의 추정치가 아니다. high의 잘못된 target도 검증해야 한다. 운영 설정·큐는 변경하지 않았다.

기존 실패 응답 3개의 오프라인 집계에서는 content 문자열이 응답 JSON UTF-8 바이트의 합계 12.9%였다. 서버가 Claim 본문을 조립할 수 있어 이 필드 생성을 생략한다. 추론 토큰을 포함한 제공자 청구 토큰의 12.9% 절감이라는 뜻은 아니다. 원문·응답 본문을 Git에 넣지 않고 [집계값](duplicate-output-audit.json)만 보존했다.
