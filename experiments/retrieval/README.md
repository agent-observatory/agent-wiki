# L4 검색 평가

고정한 합성 문서 10개·질문 8개를 실제 검색 API와 PostgreSQL로 비교했다. 실제 원문이나 모델 호출은 사용하지 않는다.

| 방식 | 기대 문서가 첫 결과인 질문 |
| --- | --- |
| 기존: 제목 일치 우선·최신순 | 3/8 |
| 검색어별 일치 수·필드 점수·조사 대안 | 7/8 |

[평가 자료](cases.json) · [측정값](results.json) · [실행 검사](../../tests/retrieval-quality.test.ts)

“임베딩 비용”에서 두 단어를 포함한 결정이 제목에 “임베딩”만 있는 참고 자료보다 먼저 나온다. `PostgreSQL은`은 원래 표현과 `PostgreSQL`을 함께 찾는다. CLI가 받는 Context에서도 순서·고정 Version을 검사한다. `%`·`_`는 검색 와일드카드로 해석하지 않는다.

**남은 실패:** “임베딩을 왜 미뤘지?”에서 “미뤘지”와 “보류”의 의미를 연결하지 못한다. 이 사례를 평가에서 숨기지 않으며 키워드 회귀 검사의 강제 통과 대상과 구분한다. 한 번 고정한 작은 개발 자료의 결과이므로 실제 질문 전반의 정확도로 해석하지 않는다. 다음 비교에서는 튜닝에 쓰지 않은 질문과 실제 지식의 관련 후보 누락을 먼저 확인한다. L2 추출 품질·결정 통합 정확도를 이 수치로 대신하지 않는다.

로컬 테스트 DB 설정 후 `npx tsx --test tests/retrieval-quality.test.ts`로 실행한다. `RETRIEVAL_REPORT`에 경로를 지정하면 현재 측정값을 남긴다. 과거 기준선은 같은 자료를 기존 검색 코드로 실행한 결과다.
