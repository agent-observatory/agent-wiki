# 에이전트 조회와 백그라운드 수집·정제

**사용자는 Claude·Codex로 하던 작업을 계속한다.** Collector는 기록 파일을 읽고, 원격 Worker가 외부 AI API로 정제한다. 수집 명령·정제 요청·대기 시간을 작업 대화에 끼워 넣지 않는다. [전체 구조](architecture.md) · [실제 배포·검증](../OPERATIONS.md).

## 사용자는 어떻게 쓰나

이전 결정이 필요할 때 에이전트가 Wiki를 조회한다. 같은 대화에서는 이미 받은 고정 개정을 재사용하고, 변경 여부가 필요하면 다시 조회한다. 검색은 L2 완료를 기다리거나 모델을 호출하지 않는다.

```sh
wiki recall --project agent-wiki
wiki search "단일 VM" --project agent-wiki
```

`recall`은 저장된 시작 문서·목차를 조회한다. 아직 수집·정제하지 못한 대화까지 기억한다고 설명하지 않는다. 웹은 지식 편집·정정·근거 확인과 수집·AI 설정을 제공한다.

## 수집·정제의 책임

| 주체 | 역할 |
| --- | --- |
| 작업 에이전트 | 사용자 질답·업무, 필요한 근거 조회 |
| 로컬 Collector | 허용 프로젝트의 Codex·Claude JSONL을 읽고 마스킹·전송 |
| Wiki API | 기록 위치·내용 해시로 중복 판단, 불변 원문과 정제 작업 등록 |
| 원격 Worker | 원문과 관련 지식 비교 → 외부 AI → 구조·인용 검사 → 지식 개정 |
| Skill·CLI | 조회·수동 관리 지침과 통신 도구. 자동 훅이나 정제 스케줄러가 아님 |

Collector는 개인 에이전트 CLI·모델 인증을 요구하지 않는다. Workspace별 원문 보관 키만 사용한다. L2는 서버에 저장한 별도 AI 키를 사용하며 사용자의 작업 대화 플랜과 분리된다.

## Collector의 처리 기준

- 명시한 프로젝트 경로와 하위 경로만 수집한다. Codex `session_meta.payload.cwd`, Claude `cwd`로 소속을 판단한다. 제외 경로·클라이언트 기록 경로는 연결 설정에서 조정한다.
- 줄바꿈까지 기록된 JSON 이벤트만 읽는다. 마지막 미완성 줄은 다음 스캔으로 미룬다. 세션 종료 여부와는 무관하다.
- 변경 감지는 완성된 기록 구간의 해시로 판단한다. 같은 크기·수정 시각을 유지한 변경도 감지한다. 변경 파일은 기록을 다시 보내고 서버가 중복을 제거한다.
- 서버는 Workspace·기기·클라이언트·세션·기록 위치·내용 해시를 사용한다. 순서가 뒤바뀌거나 중복 전송돼도 같은 기록은 한 번 적재한다. 같은 위치의 내용이 달라지면 새 원문을 추가한다. 최대 수신 위치를 연속 수신 완료 지점으로 해석하지 않는다.
- 전송 성공을 모두 확인해야 로컬 파일 상태를 갱신한다. 실패·응답 유실은 다음 주기에 재전송한다. 원본 파일 수정·삭제·대화 삽입은 하지 않는다.
- 파일 256MiB, 기록 1MB, 요청 최대 50개·목표 16KB로 제한한다. 이미지 data URL 본문은 제외 표시로 바꾸고 흔한 토큰·비밀 키와 로컬 환경에 등록한 비밀 값을 마스킹한다. 모든 비밀 탐지를 보장하지 않으므로 수집 허용 범위를 좁게 유지한다.
- 로그에는 시각·성공·중복·실패 개수만 남긴다. 삭제된 로컬 파일을 원격 삭제 지시로 취급하지 않는다. macOS는 기기당 launchd 하나로 30분마다 실행한다. 실행 중복을 막고, 잠자기 동안 실시간 수집을 기대하지 않는다.

서버 보관본은 마스킹된 JSON을 들여쓰기한 텍스트다. 원래 파일의 바이트와 동일하지 않으며, 실제 보관본의 해시·줄 번호가 인용 기준이다. 기기별 전송 상태만 로컬에 두고 프로젝트 역사·리니지는 원격에 쌓는다.

## 원문은 불변, 지식은 개정

![원문·정제 실행·지식의 리니지](../assets/wiki-lineage.svg)

| 계층 | 보존하는 것 |
| --- | --- |
| L1 원문 | 고정 보관본·해시·기록 위치. 추가 기록은 새 원문 |
| L2 정제 | 입력 원문·참고 지식 개정·제공자·모델·설정·프롬프트 버전·모델 출력·사용량·오류 |
| L3 지식 | 지식 개정·주장·원문 인용·대체 관계·반영 주체 |
| L4 조회 | 선택한 지식 개정과 인용 자료 |
| L5 활용 | 에이전트 답변·작업. 실제 활용 기록이 없으면 추적 완료라고 하지 않음 |

Worker는 원문 묶음당 최대 3개 지식을 제안하고, 같은 Workspace의 관련 지식 최대 5개를 비교한다. 사용자 결정·관찰·AI 해석·미확인을 구분한다. 전체 세션의 대규모 군집화·자동 목차 갱신은 별도 확장 범위다.

각 주장에 현재 원문의 정확한 줄 인용이 있어야 한다. 본문은 검증한 주장으로 구성하며 기존 지식 갱신은 기준 개정이 일치해야 한다. 구조·인용 검사는 사실의 진실성이나 정제 품질을 보장하지 않는다. 사람은 웹에서 확인·정정한다.

## 정제와 재시도

Workspace의 **수집·AI 정제 → AI 설정**에서 제공자·모델·API 키·입출력 한도·일일 호출 수·활성 여부를 정한다. 기본은 중지·일일 24회다. 키는 서버에서 암호화하고 저장 후 웹에 반환하지 않는다. 설정을 바꾸면 다음 작업부터 적용한다.

Worker는 PostgreSQL 작업 테이블에서 하나씩 실행한다. 일시 오류는 대기 후 최대 3회 시도하고 최종 실패는 웹에 남긴다. 인증 오류·틀린 인용·개정 충돌 등은 자동으로 반복하지 않는다. 원문이 입력 한도보다 크면 실패로 남기며 조용히 잘라 반영하지 않는다. 설정 수정 후 웹에서 재시도할 수 있다.

모델 출력 저장 뒤 종료됐다면 저장된 출력으로 멱등 반영을 복구한다. 지식 반영·작업 완료는 같은 DB 트랜잭션이다. 모델 응답 자체가 유실되면 제공자의 처리 여부를 확인할 수 없어 재호출 시 사용량이 중복될 수 있다. 일일 시도 한도에는 실패도 포함하고, 응답 없는 호출의 토큰은 미집계다. UTC 자정에 일일 한도가 갱신된다.

종료 신호에서는 새 작업을 받지 않고 진행 결과를 최대 90초 동안 마친다. 강제 종료된 작업은 5분 임대 만료 뒤 복구한다. 수집과 지식 조회는 정제의 오류·호출 한도와 별도로 동작한다.

## API 계약

경로 앞에는 `/api/workspaces/:workspaceId`를 붙인다.

| API | 용도 |
| --- | --- |
| `POST /collection` | 기기·클라이언트·세션·시작 위치·JSON 기록 → 신규/중복 개수·원문·작업 ID |
| `GET/PUT /ai-settings` | 웹 소유자 세션 전용 설정. 변경 버전 검사, 키 읽기 금지 |
| `GET /refinements` | 작업·실행·오늘 사용량·수집 상태 |
| `POST /refinements/:id/retry` | 실패 작업 재시도. 이전 실행 보존 |
| `POST /source-records` | 수동 원문 보관 |
| `GET /source-records/:id/revisions/:revision` | 고정 원문과 줄 범위 |
| `POST /publications` | 멱등 키·입력 개정·지식 변경·근거 → 반영 개정 목록 |
| `GET /publications/:key` | 반영 응답 유실 때 결과 확인 |
| `GET /recall`, `GET /context` | 저장된 지식·근거 조회. 모델 호출 없음 |

작업 에이전트는 `read`, Collector는 `source:write` 권한을 사용한다. 수동 관리·정제 CLI에는 필요할 때 `publish`를 발급한다. AI 설정은 에이전트 키로 변경할 수 없다. 객체 저장과 DB는 단일 분산 트랜잭션이 아니며 객체 저장 성공 뒤 DB 등록·작업 생성을 함께 커밋한다.

수동 반영 JSON은 [근거 계약](../../packages/cli/skill/references/publication.md)을 따른다. 일반 원문 등록은 100KB, 수집 경로는 요청 기록 합계 1MB다. 이미지 해석·PDF 파싱은 제공하지 않는다.

## 연결과 지침

에이전트 조회 연결:

```sh
npm link ./packages/cli
wiki init --project agent-wiki --workspace <Workspace-ID> --tag agent-wiki
wiki skill install
```

Collector는 **에이전트 연결**에서 원문 보관 권한의 키를 발급하고 Git 제외 `.env.local`에 `WIKI_COLLECTOR_TOKEN`으로 저장한다. 최초 한 번 설정한다.

```sh
npm link ./packages/collector
wiki-collector init --workspace <Workspace-ID> --project /absolute/project --env /absolute/project/.env.local
wiki-collector once
wiki-collector install
```

설정은 `~/.agent-wiki/collector.json`, 전송 상태·로그는 같은 디렉터리에 둔다. 여러 프로젝트는 설정의 `projects` 배열에 추가한다. Linux 등에서는 `once`를 스케줄러에 연결한다. Skill 설치만으로 Collector가 켜지지 않는다. npm 공개 배포·MCP 연결은 별도다.

macOS 자동 실행 중지:

```sh
launchctl bootout gui/$(id -u)/org.agent-observatory.wiki-collector
```

## 검증 기준

수집 중복·순서 역전·동일 크기 변경·미완성 기록·실패 후 재전송, 역할별 권한, 키 암호화, 한도와 일시 중지, 근거 반영, 임대 복구, 실제 SIGTERM 종료를 검증한다. 실제 모델 응답·원격 배포·사용자 기록의 지식화 여부는 [운영 현황](../OPERATIONS.md)에 별도로 남긴다.
